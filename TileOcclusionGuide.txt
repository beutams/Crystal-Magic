城镇碰撞的使用方法：
1. 双击 TownMap_Occlusion.prefab，选根节点，打开 Tools > Map > Tile Occlusion Editor，
   点“使用 Hierarchy 当前选择”。打开“显示红色碰撞占地”即可检查占地。
2. “批量生成碰撞占地”按类别生成：树干主体中间竖向两格（不含最下面的根影格），
   独立树桩只挡主体一格（不含周围草叶、根影），水井底部横向两格，
   房屋只识别底层房框，不参考屋顶、山墙、正立面和窗户图块；其他障碍按全部已有格子。
   房框断点沿原墙方向直连或补拐角，先补近距离缺口，连成封闭轮廓；
   轮廓内全部填成不可通行，门口缺格也封住。L 形、U 形保持实际凹边，
   外侧院子和屋檐下的地面不因屋顶覆盖而被填满。无法可靠闭合的房框会拒绝导出，
   提示手工指定碰撞，不退回整栋包围矩形。
   补墙只作用于碰撞和寻路数据，不增补美术图块，不修改 TMX。
3. 特殊组可选“画碰撞格”“擦碰撞格”或“当前组设为无碰撞”。碰撞编辑不改变遮挡格；
   修正后的组会保留，自动分组/生成碰撞不会覆盖手工修正。
4. 修改后点“导出碰撞 + 寻路配套 Prefab”，再保存显示 Prefab；需要备份/复用标注时，
   另存标注配置。导出创建新目录，旧配套文件不覆盖，避免破坏其他地图的引用。
5. 当前城镇物理文件位于 TownMap/Collision/TownMap_Occlusion_Physics.prefab。
   将这个物理 Prefab 放在对应 SubScene；显示用的 TownMap_Occlusion.prefab 留在普通场景。
   两个根节点需使用一致的世界位置和缩放，不要重复加载多份碰撞或叠加旧城镇碰撞。
   仅把显示 Prefab 拖进场景，不会自动把配套物理 Prefab 加进 ECS 世界。
6. 物理副本没有 Renderer，不会影响遮挡排序。相邻格合并成不跨越空洞的 BoxCollider，
   由 Unity Physics 烘焙成 ECS 碰撞体；同一占地烘焙成现有寻路系统的阻挡位图。
   每个 ECS 世界同时只能加载一份此类寻路地图，切换地图时需卸载上一份。
7. 物理/寻路只支持 XY 正方形网格、根节点平移及正向等比缩放，不支持旋转、镜像或
   偏离 Z=0 平面。源 TMX 的逐格翻转不影响全格占地，仍可按对应素材模板识别。
8. CollisionData 和物理 Prefab 都是导出结果，请通过工具编辑原标注再重新导出，
   不要单独移动导出碰撞块或改其中一份数据，否则物理与寻路会不一致。
9. 边缘截断树若只有一格树干就保留一格；仅露出侧边树冠或树桩外围、主体在图外的，不凭空加墙。
   原图中截断和特殊拼法会标待复核，可点“定位下一个待复核组”检查。

以后新增/修改 TMX：
1. 在 Project 中选中 .tmx，执行 Tools > Map > Auto Group Selected TMX。
2. 自动读取已导入的 TMX，识别当前 Village / AltRoofs / 补充 图集并生成新副本。
   不需要先转 Prefab；不修改原 TMX、TSX、素材和当前场景，不覆盖以前的输出。
   新生成副本现在会同时导出碰撞占地、物理/寻路配套 Prefab，配置文件包含碰撞标注。
3. 输出打开后可在遮挡工具中检查分组、调整落地点，再点“生成 / 重建遮挡显示”。
4. 在同一个已标注地图上重复“按村庄素材自动分组”，会保留通过工具手工改过的组。
   从原 TMX 再生成的新副本不会自动合并旧副本中的手工修改。
5. 需要复用手工标注时先另存配置；配置按源图层路径、格子、Sprite、翻转矩阵校验，
   不匹配时拒绝覆盖当前标注。源 TMX 重导入不会自动刷新已经导出的普通 Prefab，
   需重新生成；工具会提示配置记录的源依赖是否有变化。
6. 不认识的图集暂按遮挡物分组并标注待复核；自动识别规则只针对当前村庄素材。

一、先看样例
Tools > Map > Create Tile Occlusion Example
工具会引用现有 Village 树木和 Wizard Sprite，保存一个独立 Prefab 并打开。
左边角色在树前，右边角色在树后。沿 Y 方向拖动 Front_DragThisAnchor 或
Behind_DragThisAnchor，可以观察整棵树与角色的排序变化。样例角色只有显示，
没有移动、战斗或 ECS 逻辑。样例中的 BoxCollider2D 表示树干的占地范围。
样例在独立预览场景内生成，不改当前场景。重复点击会新建目录，不覆盖旧样例。

二、用于自己的地图
1. 把原始 Tilemap/TMX 地图的副本放入普通编辑场景。不要选择已经烘焙的
   Back/Top 大图片，也不要在 DOTS SubScene 内操作。
2. 打开 Tools > Map > Tile Occlusion Editor。
3. 在 Hierarchy 选地图根节点，点“使用 Hierarchy 当前选择”，再创建遮挡标注。
   样例中请选择 Map_SelectThisInOcclusionEditor 节点。
4. 勾选含树/房子/栅栏的源图层。不要把底下的整片草地一并选入树木组。
5. 新建组，选择“框选添加”，在 Scene 中拖选一整棵树的所有图块。
   可以多次框选，也可以“框选移除”。一个图块只能属于一个组。
6. 选择“点落地点”，点树干与地面接触的位置。房子通常点正面墙脚。
   这是排序基准，不是图片中心；自动给出的初始位置只供参考。
7. 选择与单位一致的 Sorting Layer，点击“生成 / 重建遮挡显示”。
8. 不在任何组内的图块默认当作 Ground，始终在人物后面；确实需要始终
   盖住角色的图层才选 Foreground。普通树冠/屋顶不要直接全设 Foreground。
9. 可以 Ctrl+Z / Ctrl+Y，或点击“恢复原 Tilemap 显示”。编辑源图块之前
   先恢复，编辑后重新生成。最后可“另存为可运行 Prefab”。

三、生成的是什么
- 不生成新 PNG，不改 Sprite 切片，不重画素材。
- 每组生成一个 SortingGroup，内部引用原 Sprite；整组按落地点的世界 Y
  排序，sortingOrder = RoundToInt(-Y * 100)，与当前单位排序精度一致。
- 原 Tilemap 的数据、颜色、TileFlags、TilemapCollider2D 和其他碰撞体保留。
  只关闭其 TilemapRenderer，并建立不带碰撞的显示副本。
- 剩余图块先在原图的完整邻居条件下求出外观，再保存为普通静态 Tile 快照。
  选中图块不再出现在显示副本里，刷新或重开 Prefab 不会恢复重复显示。
- 快照在 Assets/Res/Tile/OcclusionSnapshots，样例快照在各自样例目录。
  重建创建新的快照，不覆盖旧快照。恢复和撤销不会删除快照资产，避免破坏
  Undo/Redo 或以前导出的 Prefab；确认没有引用后才可手工清理旧快照。
- 原地图下的逻辑组件仍保留；若导入器在运行时重置 Renderer 状态，需要另行适配。
- 旧 Bake All Tiles 入口会拒绝再次压平已标注的地图，防止丢失动态遮挡分组。

四、当前边界
- 城镇和训练场均已接入整理过遮挡的 TownMap_Occlusion / TrainingMap_Occlusion：
  显示 Prefab 在 SubScene 外由 SceneComponent 统一管理，碰撞/寻路伴随 Prefab
  分别放在 TownSubScene / TrainingSubScene 内；不再引用旧 Training_Baked。
- 仅支持静态、XY 矩形 Tilemap。动画图层请移出处理根节点；Tile 自带
  GameObject、已有外层 SortingGroup、剪切变换和极大图层会被拒绝。
- 地图落地点支持世界 Y 在 (-299,299)，每层包围盒最多 250000 格。
- “图块里混着多个物体”与“同一张图集上有很多物体”不同。如果一个小格
  的不透明像素已把草地和树画死在一起，按格分组不能抠开这些像素。
  完全压平的地图图片也不能用本工具还原图层；应使用仍保留 Tilemap 的源图。
- 长栅栏、斜向围墙或多段前后关系不能整圈只用一个落地点。村庄自动规则已按行
  分段；其他素材手工标注时也需要遵守这一点。
- 当前每个选中图块对应一个 SpriteRenderer。先试少量障碍，再评估大地图的
  Renderer 数量和性能；本次未进行大型地图或实际联机运行性能测试。
